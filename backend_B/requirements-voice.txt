# ---------------------------------------------------------------------------
# 可选：语音合成（TTS）
# ---------------------------------------------------------------------------
# ⚠️ 默认**不需要装任何东西**。
#
# `--tts auto`（默认）按「豆包 → edge-tts → SAPI」挑第一个**真的能用**的，
# 最后那个 SAPI 是 Windows 自带的（PowerShell + System.Speech），
# 零安装、离线、答辩不怕断网。本机实测有中文音色 Microsoft Huihui Desktop，
# 合成出 16000Hz / 单声道 / 16bit 的 WAV。
#
# 实现上是一个**常驻** PowerShell 子进程：每次新起一个进程要 ~600ms 死寂，
# 常驻之后每句话只要 ~20ms。用 -EncodedCommand 传 UTF-16LE base64 的脚本
# （argv 保持纯 ASCII），待朗读文本走 stdin 传 UTF-8 base64 的文本
# （管道两边编码不同，不这样绕必然乱码）。

# 想要更自然的音色时才装这两个（--tts edge）：
# edge-tts==7.2.8   —— 微软在线音色，需要联网
# soundfile==0.14.0 —— edge-tts 硬编码输出 MP3，而标准库 wave 读不了 MP3。
#                       soundfile(自带 libsndfile 1.2.2) 负责解码，
#                       再由 audio.resample_pcm 重采样到设备能开的采样率。
#                       本机没有 ffmpeg / sox，所以只能用 soundfile。

# 豆包（火山引擎，--tts doubao / auto 的首选）**不需要在这上面加任何一行**：
# 它走标准库 urllib 发 HTTP 请求，不引 requests；
# 返回的 MP3 复用上面那个 soundfile 解码。所以「接豆包」的代价只有
# 两个环境变量，没有新依赖：
#     B_DOUBAO_TOKEN（API Key）/ B_DOUBAO_VOICE
# 可选：B_DOUBAO_RESOURCE_ID，默认 seed-tts-2.0，一般不用改。
# 详见 README.md §4.8「豆包凭证怎么配」。
#
# ⚠️ **v3（语音合成大模型 2.0 / SeedTTS 2.0）里没有 appid。**
#    旧接口（v1，/api/v1/tts）那套「appid + access_token + cluster +
#    Authorization: Bearer;<token>」在本项目的凭证下**永远**返回
#    401 "load grant: requested grant not found in SaaS storage" ——
#    换集群、换音色、换 appid 形态、甚至喂故意编的垃圾凭证，服务端回的
#    都是同一句，说明它压根没走到核对凭证那一步。现在的鉴权只要一个
#    X-Api-Key，模型版本走 X-Api-Resource-Id。
#
# ⚠️ 本机实测：到 edge-tts 的服务器（speech.platform.bing.com）**连不通** ——
#    TCP 能建连，但紧接着的 TLS 被重置。所以 auto 会跳过 edge-tts 落到 SAPI。
#    这不是 bug，是候选链在起作用；日志里会写「试合成失败，跳过」。
#    国内网络下豆包（openspeech.bytedance.com）反而是更可靠的选择。

# ---------------------------------------------------------------------------
# 关于采样率：为什么代码里到处在重采样
# ---------------------------------------------------------------------------
# **Windows 上 PortAudio 不做重采样**，声卡只接受自己的原生采样率。
# 本机实测（check_output_settings）：
#
#   [ 5] Realtek 8 声道   mono @16000 OK  @44100 OK  @48000 OK   ← 什么都收
#   [12] Realtek 2 声道   mono @16000 失败  @44100 失败  @48000 OK
#   [21] Realtek 2 声道   mono @16000 失败  @44100 失败  @48000 OK
#
# 也就是说 SAPI 合成的 16kHz WAV 往**真正的音箱**上播会直接抛
# PortAudioError: Invalid sample rate。而那个 8 声道的"能播"只是因为它内部
# 替我们重采样了 —— 声音到底去了哪几个声道没人知道。
# 所以不能靠"随便挑个能开的设备"，必须自己把采样率对上（audio.resample_pcm）。

# ---------------------------------------------------------------------------
# ⚠️ 本机注意：设备按名字选，不按索引
# ---------------------------------------------------------------------------
# 设备一律按**名字子串**解析，绝不按索引（索引会随虚拟设备增减漂移 ——
# 本机装着 ToDesk 的远程虚拟声卡，这类设备列表每次远程连接都可能变）：
#
#     python main.py --list-audio              # 先看列表
#     python main.py --audio-out Realtek       # 再显式指定
#
# 同名设备常有多个，代码会优先挑「声道数 <= 2」的：
# 搜 "Realtek" 会依次命中 [5](8声道) [11](8声道) [12](2声道) [17](2声道) …
# 第一个是环绕声端点，往它上面送单声道语音，声音去哪个音箱完全不受控。
#
# ⚠️ 更正一条**曾经写错的记录**：这里原本写「系统默认输出是
#    [4] 扬声器 (ToDesk Virtual Audio)」，实测**不成立** ——
#    PortAudio 的 MME 默认输出就是 [4] 扬声器 (Realtek(R) Audio)，
#    `sd.default.device` 返回 [1, 4]。
#    曾经那次「播放成功但听不见」的真因是 **Realtek 渲染端点的音量停在 14%**
#    （用 Core Audio 的 IAudioEndpointVolume 读出来的），把音量调回 100% 就出声了。
#    所以听不见时**先查端点音量**，再怀疑选错了设备。
