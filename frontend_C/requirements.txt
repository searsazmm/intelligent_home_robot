# ---------------------------------------------------------------------------
# 绝对不要在这里加 opencv（cv2），哪怕是为了「顺便读个图片」
# ---------------------------------------------------------------------------
# cv2 自带一整套 Qt5 插件（plugins/platforms/qwindows.dll 等），
# 和 PyQt5 的插件在同一进程里会互相顶掉对方的平台插件。
# 症状不是「颜色不对」而是直接起不来，报类似：
#
#     This application failed to start because no Qt platform plugin
#     could be initialized.
#
# 这类错误完全看不出跟 cv2 有关，极难排查。模块 C 不做任何图像处理，
# 没有任何理由引入 cv2。
#
# ---------------------------------------------------------------------------
# 关于版本号：为什么写 5.15.11
# ---------------------------------------------------------------------------
# 本机是 Python 3.14，而 PyQt5 的官方 wheel 只出到 cp38-abi3。
# **abi3 是向前兼容的**，所以 cp38-abi3 的 wheel 能装在 3.14 上
# （实测 5.15.11-cp38-abi3-win_amd64.whl 可装可用）。
# 写死版本是因为：本机出现过 「PyQt5 目录残缺、`import PyQt5` 却成功」的情况，
# 而 `import PyQt5` 成功**不能**作为装好了的判据。装完请这样验证：
#
#     python -c "from PyQt5.QtWidgets import QApplication; print('OK')"
#
# 必须用上面这条。`import PyQt5` 在一个只有空壳命名空间包的残缺安装上
# 也会成功，是假阳性。
#
PyQt5==5.15.11
